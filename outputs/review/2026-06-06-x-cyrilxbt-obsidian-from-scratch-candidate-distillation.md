# CyrilXBT Obsidian From Scratch Candidate Distillation

## Boundary

This is a candidate distillation of a user-provided X article about a simple
Obsidian setup.

It does not modify any mainline architecture, schema, template, or plugin
configuration.

## Plain-Language Takeaway

The useful part is:

```text
start from user behavior;
capture fast;
keep structure small;
review regularly;
add complexity only when pain appears.
```

For VAKS, this reinforces:

```text
Capture stays light.
Strictness is lazy.
Activation/review loops prevent forgetting.
Links and names help retrieval but do not create truth.
```

## Candidate Points

### 1. behavior_first_vault_setup

Candidate point:

```text
Vault structure should fit actual capture and review behavior rather than an
idealized organized self.
```

VAKS fit:

```text
Supports simple-first tooling and user-facing intake ergonomics.
```

Boundary:

```text
This is workflow design advice, not evidence for a specific folder schema.
```

### 2. inbox_first_capture_reduces_decision_friction

Candidate point:

```text
An Inbox reduces capture-time placement decisions, allowing later processing to

```

VAKS fit:

```text
Reinforces Capture before Understand / Review.
```

Boundary:

```text
Inbox capture is not review or knowledge.
```
