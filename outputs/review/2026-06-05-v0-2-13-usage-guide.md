# v0.2.13 Usage Guide

## 一句话

```text
轻 = 能搜到
中 = 能参考
重 = 能拿来做决定
```

v0.2.13 只管“重”：

```text
真的要拿某个 claim / 候选点 / 借鉴项去做 promotion、decision、action basis 时，
不能只列 evidence，必须写清 non-circular warrant。
```

## 1. 处理新资料时

先默认轻处理。

记录：

```text
source id / URL / file path
raw text or transcript anchor
candidate comprehension
candidate points
source-bound constraints
possible routes
project_routes_optional as routing hint only
source family / de-dup hint when useful
```

不要做：

```text
不要写 truth confidence
不要写项目已采纳
不要写 VAKS should adopt / reject
不要创建 pattern
不要创建 action basis
不要因为资料看起来有用就改主架构
```

判断句：

```text
这份资料现在只需要以后能搜到、能回源、知道大概有什么用。
```

## 2. 什么时候进中层

只有当某个点看起来有跨资料、跨项目复用价值时，才考虑中层。

中层可以是：

```text
Candidate Pattern Bank
Project Lens Overlay
  最轻解释：project-scoped sidecar overlay beside generic knowledge points
```

Candidate Pattern 只收高阶、重复出现、问题中心明确的模式。至少说清：

```text
problem addressed
mechanism
applicability
non-goals
trade-offs
source anchors / source families
risk of overreach
```

Project Lens 的最轻形态不是正式 ledger，而是 sidecar 透镜。主记录建议放在：

```text
outputs/review/project_lens_overlays/
```

Mainline status after independent Pro review:

```text
Only the generic project-scoped sidecar overlay boundary principle has landed.
The field list below is still a candidate operating convention in outputs/review, not schema, template, reviewed knowledge, ADR, or a formal mainline object.
```

Closeout status:

```text
Project Lens closeout is handled by the sandbox protocol in outputs/review/project_lens_overlays/CLOSEOUT_PROTOCOL.md.
Live Lens is scaffolding: project closeout must drain entries into landed snapshot, boundary snapshot, archive, or restricted delete+tombstone.
Archived Lens does not participate in default retrieval; tombstone never participates in semantic retrieval.
```

最小必填：

```text
project
kp_id
kp_ref
stance: watch | partial | avoid | park
borrow_scope
target_hint
reason_1liner
```

按需补：

```text
non_borrow_scope
gate_hint
review_origin
outcome_ref
updated_at
anchor_health
```

`target_hint` 建议结构化，便于 agent 定位，但仍只是可能作用位置：

```yaml
target_hint:
  - type: doc | repo_symbol | repo_line | module | workflow | pr | unknown
    value: "<locator>"
    status: active | healthy | conceptual | not_checked | drifted | unanchored
    anchor_version: "<optional version/date/commit/check note>"
```

保留名字 `target_hint`，不要改成 `code_anchor`，因为它不是“决定要改这里”，只是“未来检查这里”。

`kp_ref` 是 agent 维护时的直接回源指针：

```text
Lens Entry -> kp_ref -> Candidate Pattern / Core KP -> raw source refs
```

`conceptual` 用来标 workflow/module 这种有导航价值、但还不能像文件路径一样自动校验的目标。

不要做：

```text
不要把 active pattern 当 reviewed knowledge
不要把 stance 当 architecture adopted
不要把 Project Lens 当 ADR
不要把 Project Lens 写回原知识点 YAML / 正文
不要把 source count / reuse count 当 support strength
不要把 outcome_ref 草稿当 reviewed truth
```

判断句：

```text
这个点可以参考，但还没变成项目决定。
```

开发区最轻解释：

```text
外部资料 -> AI 蒸馏成通用知识点
当前项目 -> 通过 Project Lens sidecar 贴临时项目视角
项目结束 -> 少数真实结果快照为 landed_snapshot 或 boundary_snapshot
```

这样知识点本体保持干净，项目透镜临时可撤。

`landed` 不再是普通标签；真正用上后才产生 landed_snapshot。踩坑 / non-fit 也不只是 live tag，而是按需形成 boundary_snapshot。

当前 Project Lens 高强度沙盒结论：

```text
block-form sidecar + kp_ref + structured target_hint + conceptual status + outcome_ref snapshots
对 agent 维护有高价值。
它仍然是 candidate sidecar，不是 schema/mainline/template。
```

## 3. 什么时候触发 v0.2.13

只在这些情况触发：

```text
action_basis
significant promotion
significant decision
risk-sensitive answer relied on for action
strong relation promotion or action-critical relation judgment
explicit "is this enough?" where enough means enough to act / decide / promote
```

不触发：

```text
ordinary intake
ordinary source routing
ordinary search
simple summary
tool-directory triage
candidate-only scratch note
non-action-facing reviewer question
```

判断句：

```text
如果这个东西现在不会被拿来行动、决策、promotion，就不要开重流程。
```

## 4. v0.2.13 重层最小写法

触发后，只写这些核心项：

```text
claim
point-specific anchored evidence
non-circular warrant
scope / assumptions
known challenges / gaps
current residual review status
```

其中最关键的是 warrant：

```text
不是“我有证据”。
而是“这些证据为什么在这个 scope 下支撑这个 claim”。
```

坏 warrant：

```text
这个 claim 有证据支持，所以可以采用。
```

好 warrant：

```text
这些 anchors 都指向同一个边界：retrieval 只能把材料带到上下文里，
不能创建 reviewed relation、truth confidence 或 action readiness。
所以它们支持的是“保留 retrieval-is-activation-not-truth 边界”，
不支持“把某个检索命中当真理”。
```

## 5. 必须拦住的捷径

下面这些都不能当 support：

```text
URL only
source count
same source family repetition
tool count
vendor claim
catalogue membership
clean diagram
GSN / SACM / CAE notation
confidence label
retrieval score
rerank score
GraphRAG / vector / agentic retrieval hit
dashboard pass
AI summary
human "looks good" without evidence review
```

它们最多是：

```text
provenance
routing hint
discovery clue
candidate comprehension
review pressure
activation / context preparation
```

## 6. Agent 操作顺序

以后 agent 处理参考资料时，按这个问：

```text
1. 这只是要能搜到吗？
   yes -> light

2. 这里有可复用机制吗？
   yes -> candidate point / possible candidate pattern

3. 当前项目需要一层临时视角吗？
   yes -> Project Lens sidecar

4. 现在要拿它改架构、做决定、给行动依据吗？
   yes -> v0.2.13 action-support visibility

5. warrant 非循环吗？
   no -> blocked / insufficient / candidate-only
```
