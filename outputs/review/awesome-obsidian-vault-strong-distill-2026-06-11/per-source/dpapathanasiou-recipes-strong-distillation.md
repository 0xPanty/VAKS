# Strong Candidate Distillation: dpapathanasiou / recipes

## Boundary

This file extracts corpus/index design lessons. It does not import recipes,
component indexes, source URLs, or JSON fields into reviewed VAKS knowledge.

## What This Source Actually Is

This repository is a large JSON recipe collection generated by a separate
`recipebook` application. It contains tens of thousands of JSON records and
thousands of Markdown index pages. The README exposes two browsing modes:
alphanumeric title navigation and component navigation grouped by ingredient,
region, chef, or style.

For VAKS, this is useful as a structured-corpus and activation-index reference.
It is not a knowledge-quality reference.

## Source / Data Anchors

| Anchor | What exists | Design extraction | Boundary |
|---|---|---|---|
| `README.md` | Collection identity, generator reference, contribution note, and component index list. | A corpus can publish both source records and browsing indexes. | README is not review. |
| `index/README.md` | Alphanumeric index by number and letter. | Simple routing layer for large record sets. | Routing is not confidence. |
| `index/8/8-treasures.json` | Sample JSON with directions, ingredients, language, source, tags, title, URL. | Stable record fields support import/export and validation. | Fields are raw data only. |
| `index/a/almond.md` | Component index links many JSON recipes containing a token. | Component indexes are useful activation surfaces. | Token co-occurrence is not relation review. |
| `LICENSE` | MIT repository license. | License should be recorded separately from data provenance. | Upstream content still needs review. |

## Strong Borrow Points

1. **Separate raw records from generated indexes.**  
   JSON files are individual records; Markdown index files are navigation. VAKS
   should use the same separation for raw source cards, candidate points,
   generated dashboards, and activation maps.

2. **Multiple indexes can point to the same canonical record.**  
   A recipe can be reached by title index or component index. VAKS can borrow
   this for retrieval: query, topic, source, risk, and project indexes can all
   activate the same candidate note without changing its truth status.

3. **Component indexes are activation, not reviewed relations.**  
   Ingredient/style tokens create useful browsing paths. VAKS can adapt this
   only as association-neighborhood activation. A token link does not mean a
   reviewed concept relation exists.

4. **JSON schema is useful for import/export but weak for explanation.**  
   Fields like `directions`, `ingredients`, `source`, and `url` are easy to
   parse, but less readable than Markdown for human review. VAKS should keep
   Markdown as canonical and use JSON as export/cache where needed.

5. **License and provenance must be tracked separately.**  
   The repository has an MIT license, while individual recipe records point to
   upstream sources. VAKS should record repository license, source URL, and
   evidence support as separate checks.

| Context Pack | Multiple indexes can assemble context candidates. | Needs evidence sufficiency gate for action. |

## Local De-Dup / Collision

This overlaps with Frorozcol's CSV dataset and Grimgrains' typed generator:

- Frorozcol is strongest for dataset-card and scrape-quarantine lessons.
- Grimgrains is strongest for typed generator and strict build lessons.
- `dpapathanasiou/recipes` is strongest for large JSON records plus activation
  indexes over the same corpus.

For VAKS, this source should inform derived index design, not core truth schema.

## Anti-Borrow

- Do not treat component indexes as reviewed relations.
- Do not convert VAKS canonical notes into JSON-only records.
- Do not treat upstream `url` fields as evidence support without checking the
  specific point.
- Do not use corpus size as a coverage or confidence claim.
