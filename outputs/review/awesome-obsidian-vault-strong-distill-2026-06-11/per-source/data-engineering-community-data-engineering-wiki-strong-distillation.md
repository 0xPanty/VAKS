# Strong Candidate Distillation: data-engineering-community / data-engineering-wiki

## Boundary

This file extracts reusable structure and governance from the Data Engineering
Wiki. It does not adopt its technical claims, tool recommendations, or
community judgments as reviewed VAKS knowledge.

## What This Source Actually Is

This is a community-maintained Obsidian-native technical wiki for data
engineering. It has topic folders, templates, public publishing assets,
contribution rules, lifecycle tags, weekly link checking, and an explicit policy
against exclusively AI-generated entries.

For VAKS, its value is not "data engineering truth". Its value is the operating
shape of a public Markdown wiki that tries to stay editable, templated, and
maintained.

## Strong Borrow Points

1. **Lifecycle tags are useful routing, not confidence.**  
   `seedling`, `incubating`, and `evergreen` are good public-facing maturity
   labels. VAKS can borrow this as activation/maintenance routing, while keeping
   truth confidence separate.

2. **Templates should default to non-published candidate state.**  
   The templates include `publish: false`. That fits VAKS: source intake should
   start private/candidate and require a later gate before publication or action
   use.

3. **Contribution policy can include an AI-authorship boundary.**  
   The wiki rejects entries exclusively generated by AI because of correctness,
   authorship, plagiarism, and learning concerns. VAKS can borrow the stricter
   process boundary: AI output may draft candidate material, but it cannot stand
   in for source-grounded review.

4. **Automated link checks belong in maintenance, not truth.**  
   Weekly Lychee checks and issue creation are useful hygiene. They should
   produce review pressure, not confidence upgrades.

5. **Editable public wiki pages benefit from obvious source affordances.**  
   The templates include edit/copy/helpfulness affordances. For VAKS, similar
   affordances should point back to candidate and source records, not hide the
   derivation chain.
