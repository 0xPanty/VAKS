# Audit Shell V1 Sandbox Closeout

Status: sandbox closeout. No main-vault writeback, no `SCHEMA.md` change, no operation-convention promotion.

## Plain Verdict

The audit shell v1 direction is worth continuing, but the current landing is narrow:

- `shell_core` is the only default-core candidate.
- recurrence / grouping remains a conditional side arm.
- authority lint and categorical feedback wording are guardrails, not value engines.
- the 800 run is an automated pressure-overlay pilot with frozen machine oracle, not a completed independent human-oracle pilot.
- human timing, dual-review, and click-back validation are still future work.

## What Pro Accepted

- 800 cases across four arms.
- rendered-output checking.

But Pro was explicit that it is not product-grade:

- no independent human gold yet.

- grouping still depends on favorable fields.

## Design收束

Default core:

- hard-trigger shell
- required unresolved gate
- anchor health strip
- sparse provenance / pointer triad
- resolved folding / unresolved-first surface

Conditional side arm:

- representative / delta recurrence digest
- versioned fingerprint grouping
- only for ordinary, open-only, valid-anchor, action-meaning-stable recurrence
- must break out on action-basis, challenge, conflict, regression, anchor problem, known omission, or review_due

Guardrails:

- categorical feedback strip
- authority boundary lint
- no numeric feedback truth delta
- no count/source-count/lineage-as-confidence wording

## Human Preflight Lesson

We attempted a small A/B preflight, but stopped it as a formal user task.

The finding is useful:

The current artifacts are still too machine-like and too English-data-fixture-shaped for a Chinese reviewer.

This means the next useful alpha is not more automatic fixture expansion. The next useful alpha is:

```text
Chinese reviewer-facing shell card
```

This is not a new truth layer. It is a view-layer expression of audit shell v1.

## Key Usability Finding

Machine labels are not enough:

- `missing_anchor`
- `review_due`
- `unresolved_gate`
- `pointer_triad`
- `dashboard_as_truth is diagnostic only`

For real VAKS use, these must become Chinese reviewer-facing risk strips:

- 锚点缺失，不能回源，必须复核。
- 需要复核，暂不能作为行动依据。
- 已进入未解决队列。
- 来源 / 记录 / 证据分别可跳回。
- dashboard 只是诊断，不是事实证据。

## What Must Not Be Claimed

Do not write these into the main vault:

- `800 independent-oracle pilot passed`
- `real-data paired pilot passed`
- `authority fuzz 100% proves safety`
- `anchor retention 100% proves click-back`
- `review_proxy reduction equals human time reduction`
- `grouped reduction proves recurrence maturity`
- `group count / source count / lineage count means more confidence`
- `feedback changes truth confidence`
- `dashboard / test pass / shell summary proves correctness`
- `shell is the truth core`

## Current Stage Decision

Automatic sandbox validation is closeout-ready.

Do not keep adding broad automatic patches.

If work continues, the next narrow step should be:

1. build a Chinese reviewer-card renderer/spec for `shell_core`.
2. keep recurrence as side-arm only.
3. improve real click-back coverage if needed.
4. then run limited human timing / dual-review / click-back.

No main-vault operation convention should be promoted yet.
