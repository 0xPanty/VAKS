# Boundary Snapshot Candidate: Project Lens Becomes A Tiny ADR

## Trap Title

Project Lens written in decision language.

## Bad Move Or Non-Fit

Writing Project Lens entries as if they were context / decision / consequences records, or using stance as adoption/rejection proof.

## Failure Context

The older Project Borrowing Ledger shape invited this drift because "ledger" sounds like a record of decisions. Project Lens is safer only if it stays a sidecar overlay with weak, reversible language.

## Trigger Conditions

```text
stance is read as final project status
reason_1liner becomes a full justification essay
outcome_ref is filled before real project use
Project Lens is cited as action basis
derived ledger is used as primary authoring surface
```

## Why It Failed

Project Lens is meant to route attention during development. It is not supposed to decide architecture. If it starts carrying decision prose, agents will bypass the v0.2.13 warrant gate.

## Boundary Of Applicability

Applies to:

```text
Project Lens entries
Project Borrowing Ledger derived views
Candidate Pattern Bank project fit wording
handoff summaries
Obsidian sandbox notes
```

## Warning One-Liner

Lens is a viewing angle, not a decision record.

## Safer Alternative Or Escalation

Keep stance reversible. If the claim becomes action-facing, create a decision/review record and run the warrant gate.
