# Misa Retrieval Hints Are Not Control Authority

## Trap Title

Retrieval or perception priority silently becomes route authority.

## Bad Move / Non-Fit

Treating `suggested_priority`, attention queues, vector ranks, digest hints,
GraphRAG/community summaries, or tool-loop reports as if they can change route,
winner, memory, VPS, or execution authority.

## Failure Context

Misa has multiple useful hint surfaces:

```text
perception digest
vector ranker
component health diagnostics
Hermes runtime adapter/work-order dry-runs
sidecar status
```

These are valuable for attention and review routing. They become dangerous if
the overlay or retrieval order makes them look like support strength or action
readiness.

## Trigger Conditions

- A hint field is used as evidence support without source-specific warrant.
- A route/priority/read-order field is read as confidence.
- An active overlay entry is used to justify Misa runtime or VPS changes.
- A diagnostic candidate is consumed by an agent as a repair command.

## Safer Alternative

Keep hint surfaces as activation/context only. For any action-facing control
decision, open v0.2.13:

```text
claim
anchored evidence
non-circular warrant
scope / assumptions
known gaps / risks
residual review status
```

## Scope Boundary

This is not a universal ban on retrieval, vector ranking, dashboards, or
perception digests. It is a boundary against treating them as control authority.
