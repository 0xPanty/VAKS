# CyrilXBT Obsidian Hermes Life System Candidate Distillation

## Boundary

This is a candidate distillation of a user-provided X article about connecting
Obsidian, Hermes Agent, Claude, Filesystem MCP, and scheduled skills.

It does not install Hermes, configure MCP, connect Claude, create skills,
schedule jobs, or grant any vault access.

## Plain-Language Takeaway

The useful part is:

```text
agent-vault systems need a readable file workbench;
MCP is the real access boundary;
skill files should be explicit;
automated outputs need a visible output zone;
direct filing, direct updates, and scheduled writes are high-risk until reviewed.
```

For VAKS, this reinforces:

```text
files are workbench and receipts;
agent memory is activation, not truth;
outputs are candidates;
connections are activation;
project health is diagnostic;
CLAUDE.md updates need review;
automation is not default.
```
