# 阶段性设计采集与全貌综合落地

## 定义

当前处于开发阶段，重点不是立刻把每个优秀库的设计都塞进项目，而是先持续记录优秀设计点，积累足够样本后，再从全貌角度理解、归类、取舍和落地。

这是一条从观察到采用的流程：

```text
发现优秀库/设计
  -> 记录设计点
  -> 归类成模式
  -> 和历史项目/当前目标建立连接
  -> 周期性综合
  -> 形成落地方案
  -> 再进入项目实现
```

## 当前阶段

当前主要任务是 `harvest`，也就是采集：

- 记录优秀库的关键设计点。
- 记录为什么这个设计优秀。
- 记录它解决的问题。
- 记录它可能适合哪些项目或生产流程。
- 记录暂时不确定的地方。

这个阶段不强求立刻采用。

## 后续阶段

当积累到足够多的库分析、设计模式和阶段洞察后，再进入 `synthesis`，也就是综合：

- 找出多个优秀库反复出现的共同模式。
- 找出不同设计之间的冲突和取舍。
- 判断哪些设计适合当前项目的真实边界。
- 把可采用的设计合并成一套自己的架构语言。
- 再写入具体项目的决策记录和实施计划。

## 为什么这样做

单个优秀设计很容易让人冲动采用，但系统真正需要的是整体协调。

先采集、后综合，可以避免：

- 看到高级设计就硬加。
- 过早定型导致后面推翻。
- 每个库学一点，最后系统变得拼贴。
- 只学表面 API，没有吸收真正的设计思想。

## 落地原则

当前先允许大量观察，但落地时必须严格：

- 是否解决真实问题。
- 是否和当前系统自然衔接。
- 是否降低长期复杂度。
- 是否能被验证。
- 是否能回退。
- 是否能和其他优秀设计形成统一语言。
