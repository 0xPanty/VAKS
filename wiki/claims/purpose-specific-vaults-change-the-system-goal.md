# 主张：Purpose-specific vaults change the system goal

## 主张

同样的底层结构 Markdown vault + AI agent + instructions + skills，可以根据目的变成不同系统。Heinrich 的目标是深度思考，Yanhua 的目标是内容生产，用户的目标可以是开发 + AI 短剧生产。

## 为什么重要

这避免了盲目照搬别人的 vault 结构。我们应该提炼底层模式，再按用户目的改造，而不是复制作者的目录和流程。

## 支持证据

- Heinrich 文章明确不同 vault 需要不同 philosophy。
- Yanhua 文章把同一套理论改造成多平台内容生产流水线。
- 当前用户需求是开发项目和 AI 短剧，并不等同于单纯 PKM 或内容号。

## 反例 / 冲突证据

- 如果 purpose 过多，单一 vault 可能变复杂。
- 需要通过目录、Properties 和 Bases 明确区分不同用途。

## 验证方式

建立不同 workflow 模板：资料分析、库设计采样、AI短剧素材到分镜、内容发布。观察是否需要拆分 vault 或只拆分目录规则。

## 当前结论

高信号，支持当前“按用户目标定制资料库”的方向。

## 复查计划

当 AI 短剧和开发资料都开始大量增长时，复查是否需要拆分成多个 vault。
