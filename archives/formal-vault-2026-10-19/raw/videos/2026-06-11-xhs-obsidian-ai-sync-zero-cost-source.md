# 视频资料：Obsidian + AI 知识管理第一步：0 成本多端同步

## 为什么收录

这条小红书视频不是讲 VAKS 的证据审查，也不是讲 AI/RAG 算法。它解决的是更底层的使用问题：一个个人 Obsidian 知识库如果要长期用于 AI 知识管理，第一步可能不是先做自动总结，而是先让资料在多端可用、同步可控、备份可靠。

视频给出了一套面向非技术用户的同步取舍：官方同步、iCloud、网盘、插件同步、Git/Syncthing/LiveSync 各有门槛；作者最终选择 `Remotely Save + OneDrive`，并强调降低并行度、统一仓库名、区分主基准端和手机端、不要同步 `.obsidian` 配置文件夹、同步不是备份。

对 VAKS 的价值主要在 workbench / 操作层：它提醒我们，资料库不是只有架构和 review gate；如果用户日常打不开、同步乱套、配置互相覆盖，后面的 AI intake 和 agent 调用都跑不稳。它不能直接作为“最佳同步方案”的行动依据，具体价格、配额、插件状态和平台稳定性需要按当前时间重新核验。

## 人话摘要

视频说的是：Obsidian 多端同步有很多方案，但普通用户真正需要的是低成本、低门槛、能覆盖 Windows / Mac / iPhone / Android 的办法。作者把方案分成几类：官方同步最省心但付费；iCloud 适合苹果全家桶但 Windows 不稳；网盘同步适合纯电脑场景但手机端不理想；插件同步对多平台小白更友好；Git / Syncthing / LiveSync 更偏技术用户。

作者试过两个坑：Google Drive 插件对网络稳定性和重新授权很敏感；坚果云免费版会遇到上下行流量限制和 503。最后作者选择 `Remotely Save + OneDrive`，理由是插件时间久、下载量大、稳定性相对有保障，OneDrive 免费空间对文字仓库够用。

配置重点包括：先备份；准备微软账号和 Obsidian；安装第三方插件 `Remotely Save`；远程服务选 OneDrive；确保远端根文件夹名称和本地仓库名称完全一致；自动同步频率可设 10 分钟或半小时；并行数从默认 5 降到 1-2；按设备分配同步方向；手机端更适合增量推送；不要同步 `.obsidian` 配置文件夹；同步失败时检查“修改超过百分比则终止同步”；无论同步多稳，都要定期做独立备份。

## 我的理解 / 推断

这条视频真正可借鉴的不是“某个插件永远最佳”，而是一个低门槛 Obsidian workbench 的操作纪律：

```text
先让 vault 能稳定到达每个需要的设备。
把电脑设为主基准端。
手机只做轻输入，不承担完整仓库负载。
配置文件和内容同步分开。
同步和备份分开。
插件/云盘只是通道，不是真值层，也不是安全保证。
```

对 VAKS 来说，它更像 `Capture / Workbench Infrastructure` 候选材料：解决日常入口、碎片记录、多端可达和备份纪律。它不应该进入 reviewed knowledge，也不应该直接改 formal vault 的同步策略。

## 可抽取 Candidate Points

- Obsidian AI 知识管理的第一层基础设施是多端可达和备份纪律，而不一定是先做 AI 自动化。
- 对非技术用户，插件同步 + 云盘可能比 Git/Syncthing/LiveSync 更容易落地，但代价是需要额外关注插件稳定性和冲突处理。
- 多端同步应区分设备角色：一个主基准端负责完整双向同步，手机端可以只做轻量输入/增量推送。
- `.obsidian` 配置文件夹不应轻易跟内容仓库一起自动同步，否则容易产生跨设备配置冲突。
- 同步不等于备份；知识库需要独立、可恢复的备份习惯。
- 视频里的价格、配额和插件状态是时间敏感信息，不能不经核验用于行动依据。

## 可借鉴

- 用“主基准端 + 轻输入端”的设备角色降低同步复杂度。
- 把配置同步和内容同步分开处理。
- 把并行度、同步方向、仓库名一致性作为可见 checklist。
- 把定期手动备份作为 AI 知识库的底层安全纪律。
- 对普通用户提供“插件同步 / 技术同步 / 官方同步”的分层建议，而不是只给一种理想方案。

## 不能直接借鉴

- 不能把 `Remotely Save + OneDrive` 写成 VAKS 默认方案或最佳实践，除非后续按当前版本重新验证。
- 不能把作者的个人踩坑经验升级成普遍结论。
- 不能把同步机制当作 truth / review / action-basis 机制。
- 不能让自动同步覆盖 formal vault 的来源、候选、reviewed 层级边界。
- 不能把 `.obsidian` 配置自动同步到所有端，尤其不能影响本项目手册、模板、插件配置和执行权限。

## 风险和不确定

- ASR 中有错词，工具名和设置名主要以公开视频描述为准。
- 小红书公开视频/描述是二手经验，不是官方文档或插件源码。
- OneDrive 免费空间、Obsidian Sync 价格、插件下载量、平台稳定性都可能随时间变化。
- 如果用于真实工作流，必须先在测试 vault 验证同步方向、冲突处理、恢复能力和备份恢复。
- 对 VAKS 正式资料库，当前不建议直接把 formal vault 交给这个方案；最多作为普通用户工作台参考。
