## 人话摘要

视频展示了一个叫 APEX Dashboard 的 Obsidian 插件。作者说它是一个“一页纸工作台”：把备忘录、待办清单、项目文档、快捷链接、最近编辑放在同一个 Dashboard 页面里，减少用户在文件树里来回找东西的成本。

安装后，插件会在 vault 中自动生成一个叫 `Dashboard` 的 Markdown 笔记，用户点击小房子图标就能打开工作台。上方是 Memo 卡片，用来随手记灵感或会议要点；下面是待办清单，可以添加卡片、拖拽排序、完成后打勾，并用进度条反馈完成感。

项目文档管理部分可以关联仓库里的笔记，生成项目卡片；用户可以修改项目名，通过搜索把相关文档挂到项目卡片下。左上角是快捷链接，下面是最近编辑，用来快速回到常用文件或刚刚使用过的文件。插件还提供主题切换、Dashboard 路径设置，并声称支持桌面、平板和手机。

对 VAKS 的候选启发是：工作台层可以非常轻，但很有用。它不决定 truth，也不做 review，却能把 capture、task、project context、recent activity 和 reactivation 放到同一个入口，让用户更容易继续行动。

## 我的理解 / 推断

这条视频对 VAKS 的价值主要在 workbench / activation 层。它不是要改变知识 schema，而是说明一个统一入口能显著降低“我现在该去哪看、该接着做什么”的摩擦。

它和前几条视频可以串起来看：一条说入口太重会导致记录瘫痪，一条说系统先于工具，一条说行动反馈要回写，这条则给出一个具体入口形态：Memo、Todo、Project Docs、Quick Links、Recently Edited。对 VAKS 来说，这些都可以是候选 workbench surface，而不是 truth core。

但这也有风险：Dashboard 很容易变成漂亮控制台，让用户误以为“有仪表盘就有系统”。VAKS 要吸收的话，必须保留边界：Dashboard 是入口和激活面，不是 review、truth、evidence support 或 action readiness。

## 可抽取 Candidate Points

- 一页纸工作台可以降低 Obsidian 日常入口摩擦，把随手记录、待办、项目文档和最近文件放到一个 activation surface。
- Dashboard 自动生成和小房子入口可以减少配置成本，但不能替代系统结构或 review gate。
- Memo / Todo / Project cards 分别对应 capture、action tracking、project context，而不是 reviewed knowledge。
- 最近编辑和快捷链接适合做 reactivation 信号，不能当作可信度或重要性判断。
- 对 VAKS 来说，workbench 应该是主结构的投影，而不是新的 truth layer。

## 可借鉴

- 一页纸 workbench：Memo、Todo、Project docs、Quick links、Recently edited。
- 自动创建工作台文件，降低初始配置阻力。
- 使用卡片和拖拽表达当前项目/任务状态。
- 小房子入口作为“回到当前工作台”的稳定 affordance。

## 不能直接借鉴

- 不能把插件状态或 dashboard 卡片当 reviewed knowledge。
- 不能把待办进度当 action readiness。
- 不能把最近编辑当作 hot/truth，只能当 reactivation cue。
- 不能在未查 GitHub 代码/权限/维护状态前推荐安装或正式采纳。
- 不能让 workbench 取代 VAKS 的 source/candidate/review/action/use-ledger 边界。
