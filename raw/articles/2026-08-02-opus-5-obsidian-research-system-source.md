## 初步看点

- 按任务形状而不是品牌口号做模型路由，并在 VAKS 自身任务上验证。
- 把未决问题作为持续队列，而不是让模型猜测。
- 周报只覆盖最近增量，并作为指向完整笔记的导航层。
- 冲突必须进入人工、时间和作用域判断，不能静默覆盖。
- 摄入前先确定主题/项目作用域，跨作用域连接需显式说明。
- 成效度量同时关注遗漏、纠错、实际查询使用、成本与稳定性。

## 明显疑点

- 原始作者、发布页和发布日期缺失。
- “wiki is trustworthy”把加工状态误当成审核状态。
- 自动扩写现有笔记没有 claim identity、来源锚点、幂等处理、supersede 或 operation receipt。
- 模型路由建立在厂商/垂直领域数据上，没有 VAKS 代表性任务评测。
- Local REST API/MCP 的权限、密钥、prompt injection、回滚和无人值守写入风险没有展开。
- 两分钟 digest 和每周节省数小时是作者主张，不是本次核验结论。

## 可抽取 Candidate Points

- Workload-shaped model routing requires local evaluation.
- A visible protocol file can encode ingestion invariants and a completion check.
- Unresolved questions should persist as no-guessing review inputs.
- A weekly digest should be a bounded recent-delta pointer.
- Contradictions require human temporal/scope judgment and preserved audit history.
- Topic scope should be decided before ingestion; cross-topic links should be explicit.
- Research-system value needs coverage, omission, use, cost, and stability calibration.
