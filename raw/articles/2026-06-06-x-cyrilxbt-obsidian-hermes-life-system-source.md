## What The Source Says

The article proposes a four-layer system:

```text
Vault Layer:
  Obsidian as human-readable Markdown storage.

Connection Layer:
  Filesystem MCP gives Hermes read/write access to the vault.

Intelligence Layer:
  Hermes + Claude execute skill files against vault context.

Automation Layer:
  Hermes Scheduler runs recurring workflows automatically.
```

It also proposes:

```text
04 - HERMES-OUTPUTS as the output zone
06 - SYSTEM/CLAUDE.md as read-first steering file
seven skills:
  morning brief
  inbox processor
  project health monitor
  connection finder
  weekly vault synthesis
  research-to-notes converter
  thinking partner
```

## Source-Useful Details

Reusable details worth routing as candidate comprehension:

- Obsidian is positioned as the human-readable memory/workbench layer.
- Hermes memory alone is described as less human-readable than Markdown files.
- Filesystem MCP is the core access boundary and therefore the core risk point.
- Agent outputs should land in a visible output folder.
- Skill files should name triggers, inputs, process steps, quality standard, and
  output path.
- Project health assessments should reference specific file evidence.
- Connection finder and thinking partner outputs are useful as activation and
  review pressure, not truth.
- Automatic CLAUDE.md updates and direct inbox filing are high-risk operations
  unless separately reviewed.
