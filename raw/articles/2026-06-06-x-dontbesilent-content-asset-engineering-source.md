## What The Source Says

The article describes a local engineering workflow for a large creator content
archive:

```text
copy old materials into a new project
define rules and state before extraction
extract content units
build topic maps
build topic assembly drafts
write explicit relations
generate relation index, dedupe candidates, status overview, and Obsidian links
turn the method into a callable skill
```

The content-unit taxonomy is:

```text
QST: question
CON: concept
OPI: opinion / viewpoint
CAS: case
SOL: solution
```

The relation set named by the source is:

```text
response
explanation
proof
conflict
```

## Source-Useful Details

Reusable details worth routing as candidate comprehension:

- Old content becomes more reusable when transformed from files into callable
  units.
- The workflow starts by copying raw materials into a new project rather than
  editing the old directory.
- Rules, state, templates, and scripts come before batch extraction.
- Status files record processed, skipped, pending, and review-needed sources.
- Topic maps organize related units into reusable content surfaces.
- Assembly drafts are publishable-content skeletons, not final truth.
- Explicit relations make Obsidian browsing and checking easier.
- Batch processing should start with representative samples before scaling.
- Counts can be used as progress receipts, not evidence of correctness.
