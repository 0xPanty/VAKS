## What The Source Says

The article argues that many note-taking problems are not storage problems but
surfacing and connection problems. Its recommended workflow is:

```text
local Obsidian vault
-> Markdown notes
-> internal links
-> graph / backlinks for resurfacing
-> simple folder structure
-> core plugins before community plugins
-> templates for repeat note types
-> weekly inbox review
-> own-words writing instead of copy-paste hoarding
```

The article presents Obsidian as network thinking rather than database thinking
or filing-cabinet thinking.

## Source-Useful Details

Reusable details worth routing as candidate comprehension:

- vault is a local folder of Markdown files
- internal links are the primary connection habit
- graph view is a visibility surface for relationships and holes
- one vault is enough to start
- simple folders are enough at first: Inbox, Notes, Projects, Archive
- core plugins first: Backlinks, Daily Notes, Outline, Tag Views, Templates
- templates are useful for repeated note types
- tags should express workflow status more than topics
- note titles should often be full-sentence claims
- copying text is not the same as understanding
- weekly inbox review prevents capture from becoming permanent clutter
- Claude prompts can turn rough inputs into Obsidian-ready Markdown, but those
  outputs still need review before they become knowledge
