作者主张，Obsidian 失败通常不是因为工具太难，而是用户一开始没有完整系统图：文件归属、检索方式、连接习惯、输出目的、每日入口、AI 操作手册和持续审计没有连起来。

## 可抽取 Candidate Points

- Obsidian system design should optimize retrieval and output, not only capture and folder neatness.
- A root agent manual such as `CLAUDE.md` can make an AI assistant more project-specific, but only if permissions and write boundaries are explicit.
- Daily notes work well as a low-friction front door for capture, decisions, and open loops.
- AI-generated connection notes, pattern reports, and syntheses should be visible files, not hidden memory.
- Manual prompts such as connection finding, decision support, writing activation, and vault audit can become reusable query modes.
- Vault audit can be treated as maintenance lint: connection gaps, stale theses, missing MOCs, and overgrown topics are diagnostic signals, not truth signals.
- A staged rollout plan matters: foundation and habit should precede automation.

## 明显疑点

- The source is a personal tutorial / social article, not a reviewed paper, official spec, or executable repo.
- The proposed fixed folder taxonomy should not replace VAKS `raw / wiki / outputs / templates / tools`.
- The automation schedule should not be started from this source alone.
- Claude reading a whole vault is an appealing product story, but VAKS still needs context budgets, source buckets, permissions, and review gates.
- AI-generated compound outputs must remain candidate-only unless later reviewed.
- Plugin recommendations are usage hints, not dependency decisions.
