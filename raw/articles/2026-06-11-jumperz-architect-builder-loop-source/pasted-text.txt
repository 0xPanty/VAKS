这就是如何运行 Claude Fable 5 作为你的架构师（仅限 20 美元订阅）+ GPT 5.5 Codex 作为你的构建者……

完整系统如下：

循环是：Fable 思考……Codex 构建，仓库记住，你来判断，就这么简单……

这一切的要点在于，我们利用了 5.5 是订阅制的优势，而且它足够快，尤其是结合 /goal 使用，我们还使用最新的 Anthropic 模型作为判断/指导……

步骤 1

>创建记忆（一次性）：在你的仓库中创建 docs/HANDOFF.md。

>Codex 在每次工作会话后更新它：构建了什么，决定了什么 + 为什么，开放的分歧，下一个切片。这个文件就是为什么 30 分钟的 Fable 就足够了……它读取状态而不是问你问题。

步骤 2  将这个粘贴到 Fable（每次会话）

>你是 [项目] 的 ARCHITECT

>GPT 5.5 Codex 是 BUILDER
>你从不编写实现代码。
>你的任务：

 (1) 阅读下面的 handoff
(2) 对构建者提出的每个分歧做出裁决：接受/拒绝/修改 + 一行原因
(3) 根据 docs 中的 gates 直接判断任何 RAW 结果，忽略构建者的叙述
(4) 编写下一个切片规范：足够小适合一个 PR，严格的验收标准，明确的范围外，并强制构建者在编码前验证 API/格式与现实的一致性
(5) 标记范围蔓延和目标移动……直言不讳。不同意我。以一个可直接粘贴给构建者的块结束。

步骤 3  将 Fable 的块粘贴到 Codex，并附上这个 /goal

/goal: 执行架构师规范。规则：

PHASE 0  在任何代码之前，回复你的计划 + 你有的每个分歧，附带原因，引用仓库中的真实文件。沉默服从 = 失败。沉默范围添加 = 失败。

PHASE 1  先在 docs/ 中冻结共享合约（schemas/interfaces）；冻结后对所有人包括你都是只读的。

PHASE 2  为不相互导入的模块生成最多 3-4 个通道代理，加上一个从不编写功能代码的审阅代理：它检查每个通道是否符合规范 + 测试 + 冻结的 docs，并返回 APPROVE 或一个编号的缺陷列表。没有 APPROVE 什么都不合并。然后：提交 + 推送每个切片，仅用原始结果更新 docs/HANDOFF.md，使用表格和数字，没有解释，没有“有前景”。裁决属于架构师和人类。

步骤 4 重复 Codex 工作数小时……你只花 Fable 的几分钟时间进行判断：仲裁、证据审查、下一步规范、终止/继续决定。每工作块一个 Fable 会话。

让它真正奏效的 5 条规则

>仓库 docs 是记忆 HANDOFF.md 之外的 = 没发生

>构建者从不给自己打分

>分歧是强制性的

>在结果存在之前冻结成功标准，之后从不编辑

>将架构师时间花在判断上，构建者时间花在打字上

>架构师是边缘，构建者是双手。仓库是大脑……这样想吧……

收藏这个。你会需要的……如果你这样做，你真的不需要支付数百美元的 API 令牌。
